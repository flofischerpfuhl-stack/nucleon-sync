# GUI / CLI / API parity

The rule: everything must be doable in the dashboard, and everything must be doable by agents (CLI with `--json`, or
the local API). This document audits that rule for version 0.3.0.

Legend:

- **yes** = covered.
- **n/a** = does not apply, with the reason.
- **no** = gap, see "Open gaps" at the end.

The scope column is the minimum agent-token scope ([ARCHITECTURE](ARCHITECTURE.md) §7; two-way pairs: §10):

- `read` is free.
- `+appr.` = an agent's request waits for the user's approval.
- `UI` = only the UI token.

| Read-only Proton CLI            | yes                  | `cli`                                             |

## Open gaps

- **`daemon.json` options** cannot be edited in the dashboard or through the API. Changing them needs a daemon restart,
  and the API has no restart. `notifyCommand` stays file-only on purpose: a scoped agent token must not be able to
  make the daemon run commands. The other keys need a separate small design (a write route with validation plus a
  restart through systemd).
- **Adoption sources** (remote folders outside all pairs that the planner may search for identical content) have no
  API or dashboard screen yet.
- **`cli --allow-write`** stays CLI-only by design (see table).
